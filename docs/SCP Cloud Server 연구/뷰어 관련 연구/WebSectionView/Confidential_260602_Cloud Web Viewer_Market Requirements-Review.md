# Cloud Web Viewer — P1(Cross Section MVP) 개발 검토

기획팀 Market Requirements(2026-06-02)의 **P1: Cross Section MVP**에 대한 개발 가능성·리스크 검토. 제공 목표 일정은 **2026년 10월(~26.10)** 이다. MMI 작성 전 사전 검토 단계 문서다.

판단 근거는 현재 `scp-section-poc`(Phase 1~5) 구현 상태다. 본 PoC는 VTK 없이 브라우저에서 CT 볼륨을 메모리에 올리고, 치열궁 곡선·법선 기준으로 삼선형 보간하여 9장 단면을 실시간 생성한다.

---

## 0. Executive Summary

- **결론**: P1(Cross Section MVP, 목표 ~26.10)은 **구현 가능**하다. 9개 중 **6개는 PoC에서 검증돼 추가 개발이 없고**, 신규/보강 개발은 **2.6 Section Slice(스크롤)·2.7 Thickness**다. 2.8은 P1을 **휘발성**으로 구현하되, 주석(Annotation)은 엔진 보유, **계측(Measure)은 신규 개발**이나 기존 MPR 뷰 계측을 동일 수준으로 옮기는 작업이다.
- **가장 중요한 리스크는 성능**이다. 단면 9장 생성이 단일 스레드에서 약 **390~420 ms** 걸리는, P1에서 가장 무거운 연산이라는 점이 근본 원인이다.
  - **주 트리거 2.6(Section Slice 스크롤)** 이다. 스크롤로 표시 구간을 옮길 때마다 새 단면들을 **연속 재생성**하므로, 생성 비용이 그대로 화면 지연으로 드러난다.
  - **2.7(Thickness)** 도 가중 요인이다. 슬랩 두께를 키우면 픽셀당 보간량이 늘어 **1장 생성 시간이 증가**한다.
  - 정리하면 근본 원인은 **단면을 만드는 계산량 자체가 많다는 점**이다. 9장을 새로 만들 때마다 CPU 연산이 크게 늘어 화면 반응이 느려진다. **2.6은 이 계산을 가장 자주 일으키고, 2.7은 한 장을 만드는 계산량을 키운다.** 위치 이동(2.4·2.5)도 같은 부하지만, 이미 **스로틀**(입력이 잦아도 일정 간격으로만 다시 그려 과부하를 막는 처리)로 대응 중이다.
- **대응**: 스로틀·표시 분리는 이미 적용. 추가로 (a) 스크롤 시 표시 구간 한정·재생성 디바운스, (b) 이미 만든 단면 **캐싱**, (c) Thickness 상한·샘플 스텝 정책, (d) P2 확장 시 **Web Worker·WASM·SIMD** 재평가로 단계적으로 관리한다.
- **선행 권고(기획 완료 전)**: 신규/보강 대상인 **2.6·2.7 두 항목은 기획 확정 전에 소규모 성능 PoC를 추가로 진행**한다. 기존 단면 생성 엔진에 (1) 스크롤 연속 재생성 경로, (2) Thickness 조절을 붙여 최악 조건의 성능을 측정한다. 측정 결과로 아래 항목을 결정해 **기획서(MMI)에 반영**한다.
  - **2.6 Section Slice**: 스크롤 단위·이동 범위, 재생성 디바운스/캐싱 적용 여부, 허용 응답 지연(대화형 성능) 기준.
  - **2.7 Thickness**: Thickness **허용 범위(상한)**, 두께별 생성 시간 기준, 기본 투영 방식(MIP/Mean 등)·샘플 스텝.
- **기획 확정 상태**: P1 항목의 의미·범위는 모두 확정됐다(2.4·2.5·2.9는 PoC 수준, 2.6은 스크롤, 2.8은 휘발성). 단 **2.6·2.7의 세부 수치·정책은 위 선행 PoC 결과로 확정**한다.

## 2. 항목별 상세 검토

### 2.1 Section Layout (구현됨)

> **기능**: Section > Layout > Scout(Axial)/Panorama/Section view로 구성된 Section 레이아웃을 제공한다.
> **비고(기획)**: Clever One 수준의 다양한 레이아웃은 제공하지 않는다. · 일정 ~26.10 · 기획 PoC O

Scout(Axial) 좌상, Panorama 좌하, Section 3×3 우측 그리드 레이아웃이 PoC에 있다. 기획도 "Clever One 수준의 다양한 레이아웃은 제외"로 명시해 범위가 좁다.

- **가능성**: 충분. 그대로 제품화 가능한 수준.
- **리스크**: 화면 비율·반응형, 단면 개수(3×3 고정 vs 가변)는 다른 항목과 함께 정리.

### 2.2 Draw Curve (구현됨)

> **기능**: Section > Draw Curve > Scout view에서 커브를 입력할 수 있다.
> **비고(기획)**: Default Curve 기능은 제공하지 않는다. · 일정 ~26.10 · 기획 PoC O

Scout에서 Catmull-Rom 제어점으로 곡선을 그린다. 기획이 "Default Curve(자동 검출) 제외"로 명시해, 사용자가 직접 그리는 범위만 본다.

- **가능성**: 충분.
- **리스크**: 자동 치열궁 검출(OpenCV 등 레거시 경로)은 P1 범위 밖. 사용자가 매번 수동으로 그려야 하는 UX 부담은 기획과 합의된 상태로 본다.

### 2.3 Edit Curve — Point 추가/이동/삭제 (구현됨)

> **기능**: Scout view > Edit Curve > Scout view에서 Point를 편집(추가/이동/삭제) 할 수 있다.
> **비고(기획)**: (없음) · 일정 ~26.10 · 기획 PoC O

`useCurveEditor`에 Edit 모드가 있고 제어점 추가·이동·우클릭 삭제가 동작한다.

- **가능성**: 충분.
- **리스크**: 점 삭제 시 곡선 최소 점수(2개) 보장, 편집 중 Section 재계산 억제 등 UX 디테일 정리만 남음.

### 2.4 Scout view — Sectional Line 위치 조절 (구현됨, 추가 개발 없음)

> **기능**: Scout view > Sectional Line > Scout view에서 Sectional Line 위치를 조절할 수 있다.
> **비고(기획)**: (없음) · 일정 ~26.10 · 기획 PoC O

곡선 모양 편집과 별개로, Sectional Line 위치 조절은 PoC에 이미 구현돼 있다.

- 현재 동작: Edit Curve를 끈 상태에서 Scout를 클릭/드래그하면 곡선 위 가장 가까운 호장 위치로 `sectionCenterMm`가 이동하고, 9개 단면선(빨간 수직선)이 **곡선을 따라 함께 미끄러진다**. 곡선 자체는 바뀌지 않는다.
- 즉 "커브 편집(모양 변경)"과 "Sectional Line 위치 이동(곡선 위 슬라이드)"은 **모드로 분리**되어 있다.
- 동작 방식은 9개 단면 묶음을 곡선 따라 **통째로 이동**하는 것이다(개별 선 하나만 따로 옮기는 방식은 아님).

**기획 결정**: 현재 PoC 수준(묶음 이동)으로 제공한다. → **추가 개발 없음.**

### 2.5 Panorama view — Sectional Line 위치 조절 (구현됨, 추가 개발 없음)

> **기능**: Panorama view > Sectional Line > Panorama view에서 Sectional Line 위치를 조절할 수 있다.
> **비고(기획)**: (없음) · 일정 ~26.10 · 기획 PoC O

"무엇을 조절하는가"는 기획 요구사항 문서의 P1/P2 분리로 정의된다.

- P1(이번): **Sectional Line 위치 조절** → 위치(곡선 따라 슬라이드).
- P2(이후): **Sectional Line의 축을 조절** → 각도(회전).
- P2(이후): **Horizontal Center Line** → 단면 이미지의 세로 중앙 위치.

따라서 P1의 "위치 조절"은 **각도·간격이 아니라**, Panorama 위 세로선 묶음을 좌우로 옮겨 `sectionCenterMm`를 바꾸는 것이다. PoC에 이미 있다.

- 현재 동작: Panorama의 굵은 중앙 세로선을 좌우 드래그하면 9선이 함께 이동(Scout와 동일 상태 공유). 위·아래 가로 핸들은 Z 상·하한(Top/Bottom) 조절.
- **간격**: 간격(INT)은 별도 항목(2.6/2.7)이며 위치 조절과 무관하게 일정하게 유지된다.
- **각도**: 회전은 P2이므로 이번 범위가 아니다.

**기획 결정**: 현재 PoC 수준(위치 슬라이드)으로 제공한다. → **추가 개발 없음.**

### 2.6 Section view — Section Slice 변경 (미구현, 의미 가장 불명확)

> **기능**: Section view > Section Slice > Section view에서 Slice를 변경할 수 있다.
> **비고(기획)**: Cross sectional image의 범위를 변경하면서 볼 수 있다(scroll 등을 통해). · 일정 ~26.10 · 기획 PoC X

기획 메모로 의미가 확정됐다. **곡선 전체에 INT 간격으로 늘어선 다수의 단면 중, 스크롤 등으로 화면에 보이는 범위(어떤 구간의 단면들)를 이동**하며 보는 기능이다.

근거: Clever One 캡처에서 Section 그리드 칸에 인덱스 번호(예: 68~76)가 붙고 하단에 `Total Slice (256/381)`가 표시된다. 즉 곡선 전체에 수백 개 단면이 있고, 그리드는 그중 연속된 일부(예: 9개)만 보여주며 스크롤로 표시 구간을 바꾼다.

- 현재 PoC: 항상 `sectionCenterMm` 중심으로 9개만 생성한다. 전체 시퀀스를 인덱싱·페이징하는 개념이 없다.
- 추가 필요: (1) 곡선 전체 단면 개수 산출, (2) 현재 표시 시작 인덱스 상태, (3) 휠·스크롤로 인덱스 이동, (4) 칸에 인덱스 라벨. 2.4·2.5(Sectional Line 위치)와 **상태 연동** 필요(스크롤하면 Scout/Panorama 선도 같이 이동).
- 난이도: 중간. 단면 생성 로직 자체는 재사용하고, 인덱싱·네비게이션 UI가 신규다.
- 리스크: 스크롤 시 다수 단면을 연속 재생성하므로 **성능 관리**가 필요하다. 스로틀·표시 구간 한정·캐싱(이미 만든 단면 재사용)으로 대응한다.

### 2.7 Section view — Thickness / Interval 설정 (일부 구현)

> **기능**: Section view > Thickness/Interval > Section view의 Thickness/Interval을 설정할 수 있다.
> **비고(기획)**: (없음) · 일정 ~26.10 · 기획 PoC O

먼저 용어를 구분한다. 단면 한 장은 서로 **독립된 세 축**을 가진다. 2.7이 다루는 것은 이 중 **Interval과 Thickness 둘**이며, 치열궁을 따라가는 방향(근원심)의 개념이다.

| 축 | 방향 | 의미 | 2.7 해당 |
| --- | --- | --- | --- |
| **Interval(INT)** | 치열궁 접선(근원심) | 인접 단면 사이 **간격** | O |
| **Thickness(슬랩 두께)** | 치열궁 접선(근원심) | 단면 평면에 **수직으로 합치는 깊이** | O |
| Width(Sec 폭) | 법선(협설, B/L) | 단면 이미지의 **가로 표시 범위** | X — 요구사항 미포함(PoC 부가) |
| Height(Sec 높이) | Z(수직) | 단면 이미지의 **세로 표시 범위** | X — 별도 P2(Panorama Height) |

- **Interval(INT)**: 구현됨. Scout 하단 슬라이더로 호장 간격(mm) 조절, 9장에 즉시 반영. 현재 기본값 1mm.
- **Thickness(슬랩 두께)**: 단면 평면에 수직인 근원심 방향으로 ±`slabHalfWidthMm`만큼의 복셀을 모아 한 픽셀로 합친다(MIP/평균 등). 현재 **고정값**이며 사용자 조절 UI가 없다. 기본 `slabHalfWidthMm = 3` → **전체 두께 6mm**, 0.5mm 간격으로 13개 샘플, 투영은 기본 MIP. → **2.7의 실제 개발은 이 Thickness 조절 UI 추가**다.
- **Width/Height는 2.7과 다른 축**이다. Sec 폭(협설)·Sec 높이(Z)는 "이미지가 보여주는 범위"이며 PoC에 슬라이더가 이미 있으나, 분류는 2.7(Thickness/Interval)과 다르다.
  - **Sec 높이(Z)**: 요구사항의 **P2 "Panorama Height"**(~27.03)와 같은 Z 범위(top/bottom 공유)를 조절한다. 즉 **P2 항목을 PoC에서 선구현**한 상태다.
  - **Sec 폭(협설)**: 요구사항(P1/P2/Future)에 **대응 항목이 없다.** CleverOne은 ScoutView 녹색 평행선으로 폭을 조절하나, 이번 기획 목록엔 미포함된 PoC 부가 기능이다.
- 추가 필요: Thickness 슬라이더 + 드래그 중 커밋 지연(폭/높이와 동일 패턴).
- 리스크: 슬랩 두께·샘플 스텝이 커지면 1장당 보간량이 늘어 **생성 시간 증가**(현재 9장 약 390~420 ms 수준). Thickness 상한·스텝 정책 필요. Worker/WASM은 후속 과제.
- **Thickness 상한은 PoC로 결정**한다. 상한 기준은 두 가지다.
  - **성능 상한**: 한 픽셀당 샘플 수 = 전체 두께 / 샘플 스텝(예: 6mm·0.5mm → 13샘플). 두께가 커질수록 생성 시간이 비례해 늘고, 2.6 스크롤과 겹치면 부하가 곱으로 늘어난다. → 두께별 1장 생성 시간 곡선 측정.
  - **영상 품질 상한**: 너무 두꺼우면 앞뒤 구조가 겹치거나(MIP) 뭉개져(Mean) 진단 가치가 떨어진다. → 두께별 샘플 영상(예: 2/6/10/16mm) 비교.
  - 상한은 위 둘 중 **더 낮은 값**으로 정한다. 함께 **기본값**(현재 6mm 유지 여부)과 **스텝 정책**(두께가 커지면 스텝도 키워 샘플 수 억제)도 결정한다.

**Thickness와 Interval의 관계(중복 포함)**: 전체 Thickness가 Interval보다 크면, 같은 복셀이 인접한 여러 단면의 슬랩에 **중복 포함**된다. 현재 기본값(두께 6mm, INT 1mm)에서는 한 복셀이 약 6장(±3mm / 1mm)에 걸쳐 들어간다. 슬랩 MIP/평균 단면에서는 정상적인 동작이며, 인접 단면이 부드럽게 이어져 보이는 이유이기도 하다. 두께를 Interval보다 작게 주면 단면 간 겹침 없이 분리된다.

기획 비고상 Scout/Panorama의 Thickness/Interval은 P2, **Section view의 Thickness/Interval만 P1**이다. 범위는 Section 한정으로 본다.

### 2.8 Section — Annotation / Measure Tool (P1: 휘발성으로 구현 / 주석 엔진 보유·계측 신규)

> **기능**: Section > Tool > Section 레이아웃에 Annotation/Measure Tool을 입력할 수 있다.
> **비고(기획)**: MPR 레이아웃과 동일한 툴을 제공한다. 기존 대비 툴 확장도 검토(Arrow 등). 현재 Length, Free Draw, Angle 제공 중. · 일정 ~26.10 · 기획 PoC X

기능을 **Annotation**(주석)과 **Measure**(계측) 둘로 나눠 본다.

- **Annotation(주석)**: 리포트 연구(PoC-14 Element 렌더링 엔진)에서 **엔진을 이미 확보**했다. 단면 뷰 위에 얹는 수준이라 부담이 작다.
- **Measure(계측)**: 우리가 따로 개발해 둔 것은 **없다. 신규 개발이 필요**하다. 다만 기획자에 따르면 계측은 기존 **MPR 뷰에 이미 구현**돼 있어, Cross Section view에도 **동일 UI·요구사항 수준으로 구현 가능**하다(Length·Angle 등).

> 기획자 의견: "계측 기능과 image filter 기능은 기존 MPR 뷰에 이미 구현되어 있는 기능입니다. (Cross Sectional View에도 동일하게 적용 가능하지 않을까 싶습니다)"

image filter는 P2이므로 본 항목에서는 제외한다.

**P1 결정: 휘발성(세션 한정)으로 구현한다.** 영구 저장은 이번 범위에서 제외하며, 도입 시점은 미정이다.

- 화면에만 주석·계측을 올리고, 곡선·간격·폭·Z 등 단면 생성 파라미터가 바뀌면 **자동 소거**한다.
- 단면 좌표(u,v mm)는 이미 mm 정합(`tileMmMetrics`)이 되어 있어 길이·각도 계측이 가능하다.
- 난이도: Annotation은 낮음(엔진 재사용), Measure는 신규지만 MPR 계측을 동일 수준으로 옮기는 작업이라 낮음~중간.

**CleverOne 동작(참고)**: CleverOne은 주석·측정을 **CT 프로젝트 파일에 저장**하는 것으로 보인다. CT를 다시 불러와 Section view를 열면 과거 주석·측정이 그대로 복원된다. 즉 영구 저장 + 단면 재생성 시 복원을 지원하는 구조다.

**영구 저장 시 선결 과제(향후)**: 저장을 도입하려면 **CT 프로젝트 파일 포맷을 먼저 파악**해야 한다(주석·측정이 어떤 좌표·기준으로 저장되는지 포함). 단면 영상은 곡선·간격·폭·Z·투영에 따라 달라지므로, 저장은 단면 픽셀이 아니라 **환자(볼륨) 좌표 기준**으로 보관하고 단면 재생성 시 다시 투영하는 방식이 유력하다. 본 과제는 P1 범위 밖이며 별도 과제로 다룬다.

### 2.9 Section — Windowing (구현됨, 추가 개발 없음)

> **기능**: Section > Windowing > Section 레이아웃의 모든 view에 Windowing을 조정할 수 있다.
> **비고(기획)**: (없음) · 일정 ~26.10 · 기획 PoC O

WC/WW가 Scout·Panorama·Section에 **공유**되어 한 번 조절하면 모든 view에 반영된다.

- CT 프로젝트 파일에도 windowing 정보가 있으나, **이번 P1에서는 연동하지 않는다**(현재 PoC와 동일하게 기본/사용자 조절값 사용).
- 프로젝트 파일 windowing 연동은 2.8 영구 저장과 마찬가지로 **프로젝트 파일 포맷 파악 이후**의 별도 과제로 둔다.

**기획 결정**: 현재 PoC 수준(공유 WC/WW, 프로젝트 파일 미연동)으로 제공한다. → **추가 개발 없음.**

## 4. 종합 결론·권고

- **P1 9개 중 6개**(Layout, Draw Curve, Edit Curve, Scout/Panorama Sectional Line, Windowing)는 **현재 PoC 수준으로 제공**하기로 확정돼, **추가 개발 없이** 제품화 정리 수준이다.
- **2개**(Section Slice 변경, Section Thickness)만 **신규/보강 개발**이 필요하나 난이도 중간이며 기존 생성 로직을 재사용한다. Section Slice는 스크롤로 단면 범위 이동(기획 메모 확정).
- **2.8 Annotation/Measure**: 주석(Annotation)은 리포트 엔진을 이미 보유했고, 계측(Measure)은 우리가 개발한 바 없어 **신규**지만 기존 **MPR 뷰의 계측을 동일 수준으로 옮기는** 작업이라 부담이 제한적이다. **P1은 휘발성으로 구현**해 10월 일정 내 가능하다. 영구 저장은 범위 밖이며 도입 시 **CT 프로젝트 파일 포맷 파악**이 선결 과제다(별도 과제, 5장 Future 연계 참고).
- 공통 리스크는 **성능**이다. Thickness·단면 개수·스크롤이 늘면 생성량이 증가한다. 현재 단일 스레드에서 9장 약 390~420 ms 수준이며, 대화형 응답을 위해 스로틀·표시 분리가 적용돼 있다. P1 범위에선 수용 가능하나, P2 확장 시 Worker/SIMD 재평가가 필요하다.

권고: P1은 **실질적으로 신규 개발 부담이 작다**(2.6 Section Slice·2.7 Thickness 신규/보강, 2.8 계측은 MPR 기능 이식). 이 항목들 기준으로 MMI를 작성하면 된다. 2.8은 P1 휘발성으로 진행하고, 영구 저장·프로젝트 파일 windowing 연동은 프로젝트 파일 포맷 분석 후 별도 일정으로 분리한다.

## 5. 참고 — Future 연계(저장·협업)

기획 요구사항 문서의 Future 항목이 2.8 주석/측정의 영구 저장(= Future 과제)과 직접 연결된다. 영구 저장은 독립 기능이 아니라 아래 Future 기능과 **한 덩어리**로 설계해야 한다.

| Future 항목 | 내용(요약) | P1 검토와의 연결 |
| --- | --- | --- |
| Project File 공유·실행 | CT 프로젝트 파일을 포함해 공유/실행 | 주석·측정의 **영구 저장 위치가 곧 프로젝트 파일**일 가능성. 2.8 "포맷 파악" 과제와 동일 작업. |
| Project File 실행 표시 | Implant·Volume Measure·Sinus Graft·ROI·정합 STL·Segment 표시 | 프로젝트 파일에 주석 외 **다양한 객체**가 함께 저장됨. 공통 객체 모델(환자 좌표) 필요. |
| Secondary Sharing | 캡처 이미지 재공유(캡처 저장 선행) | 별도 **캡처(스크린샷) 저장** 기능이 먼저 있어야 함(2.8 주석/측정과는 구분). |
| Comment | 오버레이에 코멘트 입력 | 주석·측정 객체에 **코멘트 연결** 필드를 미리 고려. |
| Overlay Navigation | 오버레이 입력 뷰로 자동 전환 | 주석을 **환자 3D 좌표**로 저장하면 위치 점프가 쉬워짐(단면 픽셀 저장은 불가). |
| Save to EzServer | 프로젝트 파일을 EzServer 저장 → Clever One 실행 | 저장 포맷은 **Clever One·EzServer와 공통 규격**이어야 함(독자 포맷 지양). |

종합: 2.8 주석·측정을 영구화할 때는 **단면 픽셀이 아니라 환자(볼륨) 3D 좌표 기준**으로 저장하는 것이 유력하다. 그래야 단면 재생성 시 재투영, Overlay Navigation, 프로젝트 파일·EzServer 연계가 한 번에 풀린다. 이 작업은 **Future Project File 착수 시점에 함께 설계**하는 것이 효율적이다.

## 6. 부록 — P1에서 굳혀둘 P2/Future 대비 설계 메모

본 검토 범위는 **P1**이다. P2·Future 자체 검토는 범위 밖이나, **P1 단계의 설계 결정 중 나중에 되돌리기 비싼 항목**만 미리 짚어 둔다. 추가 개발이 아니라 **구조·인터페이스를 막지 않는 수준**의 사전 고려다.

**P2(기능 확장) 대비**

- **단면 개수 일반화**: P2 "Section view 단면 개수 변경"을 대비해 9장 하드코딩 대신 **N장 파라미터화** 여지를 남긴다.
- **Thickness/Interval 일반화**: P2에서 Scout·Panorama에도 Thickness/Interval이 확장되므로, 2.7에서 만드는 **Thickness/Interval 모델을 view 공통**으로 설계한다.
- **다축(MPR) 곡선 입력**: P2 "Axial/Sagittal/Coronal 축 조정 후 커브 입력"을 대비해, 곡선·법선 계산을 **축(평면) 비종속**으로 추상화해 둔다.
- **성능 경로 격리**: P2 확장 시 부하가 커지므로, 단면 생성 경로를 **Worker/WASM로 옮길 수 있게** 인터페이스를 분리해 둔다(2.6·2.7 선행 PoC에서 자연스럽게 검토됨).

**Future(저장·협업) 대비**

- **주석 좌표계**: P1 주석/측정은 휘발성이라도 좌표를 단면 픽셀이 아닌 **환자(볼륨) 3D 좌표**로 다루면, Future 영구 저장·공유 시 재투영·Overlay Navigation이 그대로 풀린다(5장 참고). **영구 저장 자체는 Future 범위**이며 P1에서 구현하지 않는다.

이 메모는 **P2/Future를 지금 개발하자는 것이 아니라**, P1 구현 시 위 항목을 막지 않도록 인터페이스를 열어두자는 권고다.
