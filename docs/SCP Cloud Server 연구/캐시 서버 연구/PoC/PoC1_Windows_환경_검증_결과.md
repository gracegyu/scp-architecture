# PoC #1 Windows 환경 검증 결과 보고서: Linux vs Windows 하드웨어 사양 및 비용 비교

## 1. 개요

### 1.1 검증 목표

PoC1에서 Linux 환경만 검증되었으므로, Windows 환경에서의 로컬 캐시 서버 구축 가능성과 하드웨어 납품 전략을 검증한다. 특히 별도의 캐시 머신을 하드웨어까지 납품하는 전략에 있어 Linux와 Windows 환경의 하드웨어 사양, 라이선스 비용, 운영 비용을 비교하여 최적의 운영체제 선택 근거를 마련한다.

### 1.2 검증 범위

- Windows Server 환경에서의 캐시 서버 구축 가능성 검토
- 병원 규모별 표준 하드웨어 사양 산정 (동일 성능 기준)
- Linux vs Windows 하드웨어 및 라이선스 비용 비교
- 운영체제 선택에 따른 TCO(Total Cost of Ownership) 분석
- Windows 대신 Linux를 선택해야 하는 이유 검토

**중요 가정**: Linux는 Windows보다 성능이 우수하므로, 동일한 성능 요구사항을 만족하기 위해 Linux는 더 낮은 사양의 하드웨어로도 충분하다. 본 문서에서는 동일 성능 기준으로 Linux는 낮은 사양, Windows는 높은 사양의 하드웨어를 사용한다고 가정한다.

### 1.3 기본 가정

**병원 규모별 환자 수 및 데이터 용량 (참고: AWS 인프라 비용 분석 문서)**

| 병원 규모 | 일일 진료 환자 수 | 누적 환자 수 | 환자당 이미지 용량 | 총 저장 용량 | 캐시 용량 (1/10) |
| --------- | ----------------- | ------------ | ------------------ | ------------ | ---------------- |
| 소형      | 200명/일          | 1,000명      | 1GB                | 1TB          | 100GB            |
| 중형      | 500명/일          | 10,000명     | 1GB                | 10TB         | 1TB              |
| 대형      | 1,000명/일        | 50,000명     | 1GB                | 50TB         | 5TB              |

**참고**: 캐시 용량은 전체 저장 용량의 1/10로 산정하였으며, 실제 운영 시 캐시 히트율과 데이터 접근 패턴에 따라 조정 가능하다.

## 2. Windows 환경 검증 결과

### 2.1 Windows Server 호환성 검증

**검증 항목**

| 항목               | 결과 | 비고                                         |
| ------------------ | ---- | -------------------------------------------- |
| Nginx OpenResty    | 가능 | Windows용 바이너리 제공, 서비스 등록 가능    |
| Rust 서비스        | 가능 | Windows 네이티브 빌드 지원, 서비스 등록 가능 |
| PostgreSQL         | 가능 | Windows 설치 패키지 제공                     |
| Docker Desktop     | 가능 | Windows Server 2019/2022 지원                |
| NSIS 설치 프로그램 | 가능 | Windows Installer 생성 가능                  |
| 방화벽 설정        | 가능 | netsh 명령어 또는 PowerShell로 자동화 가능   |
| 서비스 등록        | 가능 | sc 명령어 또는 NSSM 사용 가능                |

**검증 결과 요약**

Windows Server 환경에서도 PoC1에서 선정된 기술 스택(Nginx OpenResty, Rust 서비스)을 모두 사용할 수 있음을 확인하였다. 다만, Linux 환경 대비 다음과 같은 차이점이 있다:

- **설치 복잡도**: Windows는 서비스 등록 및 방화벽 설정이 Linux보다 다소 복잡함
- **리소스 사용량**: Windows Server는 기본 리소스 사용량이 Linux보다 높음
- **라이선스 비용**: Windows Server 라이선스 비용이 추가로 발생함

### 2.2 Windows 환경 제약사항

**기술적 제약**

1. **Docker Desktop 제약**: Windows Server에서는 Docker Desktop 사용 시 Hyper-V 가상화 필요, 리소스 오버헤드 발생
2. **파일 시스템 성능**: NTFS는 Linux ext4 대비 대용량 파일 처리 성능이 다소 낮음
3. **서비스 관리**: systemd 대신 Windows Service 사용으로 관리 스크립트 복잡도 증가

**운영적 제약**

1. **라이선스 관리**: Windows Server 라이선스 갱신 및 CAL(Client Access License) 관리 필요
2. **보안 업데이트**: Windows Update 자동화 설정 필요, 재부팅 필요 시 다운타임 발생 가능
3. **원격 관리**: RDP 또는 PowerShell 원격 접근 필요, Linux SSH 대비 보안 설정 복잡

## 4. Windows 대신 Linux를 선택해야 하는 이유

### 4.1 비용 효율성

**초기 구축 비용**

- Linux: 운영체제 라이선스 비용 없음 (0원)
- Windows: Windows Server 2022 Standard 라이선스 비용 약 780,000원 추가
- **초기 절감액(라이선스만 기준)**: 규모와 무관하게 약 78만 원 수준

**운영 비용**

- Linux: 라이선스 갱신 비용 없음, 보안 업데이트 무료
- Windows: 라이선스 유지/업그레이드, 소프트웨어 보증 계약 등으로 연간 약 300,000원 수준 추가 발생 가정
- **3년 기준 추가 라이선스·유지 비용**: 약 900,000원

**3년 TCO 비교 (동일 성능 기준, KRW 기준)**

- 소형 클리닉: Linux 약 760,000원 vs Windows 약 2,755,000원 → **약 2,000,000원 절감, 비율로 약 3.6배**
- 중형 클리닉: Linux 약 1,115,000원 vs Windows 약 3,180,000원 → **약 2,000,000원 이상 절감, 비율로 약 2.8~2.9배**
- 대형 클리닉: Linux 약 2,040,000원 vs Windows 약 4,300,000원 → **약 2,200,000원 절감, 비율로 약 2.1배**

요약하면, **3년 TCO 기준으로 Linux는 Windows 대비 대략 2~3.5배 수준의 비용 절감**을 제공하며, 특히 소형/중형 규모에서 효과가 크다.

### 4.2 성능 및 리소스 효율성

**메모리 사용량**

- Linux: 최소 메모리 요구사항 낮음 (소형 8GB, 중형 16GB, 대형 32GB)
- Windows: 기본 리소스 사용량 높음 (소형 16GB, 중형 32GB, 대형 64GB)
- **차이**: Windows는 Linux 대비 약 2배 메모리 필요

**디스크 I/O 성능**

- Linux: ext4 파일 시스템이 대용량 파일 처리에 최적화
- Windows: NTFS는 Linux 대비 대용량 파일 처리 성능 다소 낮음
- **영향**: 캐시 서버의 핵심 기능인 디스크 I/O 성능에서 Linux 우위

**CPU 사용률**

- Linux: 기본 프로세스 오버헤드 낮음
- Windows: Windows Update, Defender 등 백그라운드 프로세스로 인한 오버헤드
- **영향**: 동일 하드웨어에서 Linux가 더 높은 처리량 제공 가능

### 4.3 안정성 및 운영 편의성

**업데이트 및 재부팅**

- Linux: 핵심 업데이트는 재부팅 없이 적용 가능 (live kernel patching)
- Windows: 보안 업데이트 시 재부팅 필요, 다운타임 발생 가능
- **영향**: 24/7 운영이 중요한 캐시 서버에서 Linux가 유리

**서비스 관리**

- Linux: systemd 기반 서비스 관리로 스크립트 자동화 용이
- Windows: Windows Service 관리가 상대적으로 복잡, PowerShell 스크립트 필요
- **영향**: 원격 관리 및 자동화 측면에서 Linux 우위

**로그 및 모니터링**

- Linux: 표준 로그 시스템(syslog) 및 다양한 모니터링 도구 지원
- Windows: Event Log 시스템이 Linux 대비 복잡, 모니터링 도구 제한적
- **영향**: 운영 모니터링 및 문제 해결 측면에서 Linux 우위

### 4.4 보안성

**보안 업데이트**

- Linux: 커뮤니티와 기업의 지속적인 보안 업데이트, 빠른 패치 배포
- Windows: Microsoft의 정기 보안 업데이트, 월별 패치 배포
- **영향**: 취약점 대응 속도에서 Linux 우위

**기본 보안 설정**

- Linux: 최소 권한 원칙, 기본적으로 불필요한 서비스 비활성화
- Windows: 기본적으로 많은 서비스 활성화, 보안 설정 필요
- **영향**: 초기 보안 설정에서 Linux 우위

**취약점 노출**

- Linux: 오픈소스 특성상 취약점 발견 시 빠른 패치 배포
- Windows: 상용 소프트웨어 특성상 패치 배포 지연 가능
- **영향**: 보안 대응 속도에서 Linux 우위

### 4.5 유연성 및 확장성

**하드웨어 호환성**

- Linux: 다양한 하드웨어 플랫폼 지원 (x86, ARM 등)
- Windows: 주로 x86/x64 플랫폼 지원, ARM 지원 제한적
- **영향**: 하드웨어 선택의 유연성에서 Linux 우위

**커스터마이징**

- Linux: 소스 코드 수정 및 커스터마이징 가능
- Windows: 소스 코드 접근 불가, 제한적 커스터마이징
- **영향**: 특수 요구사항 대응에서 Linux 우위

**컨테이너 및 가상화**

- Linux: Docker 네이티브 지원, 가상화 오버헤드 낮음
- Windows: Docker Desktop 사용 시 Hyper-V 필요, 오버헤드 발생
- **영향**: 컨테이너 기반 배포에서 Linux 우위

### 4.6 생태계 및 커뮤니티

**오픈소스 생태계**

- Linux: 풍부한 오픈소스 도구 및 라이브러리
- Windows: 상용 소프트웨어 중심, 일부 오픈소스 도구 제한적
- **영향**: 개발 및 운영 도구 선택의 폭에서 Linux 우위

**커뮤니티 지원**

- Linux: 활발한 커뮤니티, 풍부한 문서 및 예제
- Windows: Microsoft 공식 지원 중심, 커뮤니티 상대적 제한
- **영향**: 문제 해결 및 학습 자료에서 Linux 우위

**장기 지원**

- Linux: Ubuntu LTS 버전은 5년간 지원, 장기 안정성 보장
- Windows: Windows Server는 주기적 버전 업그레이드 필요
- **영향**: 장기 운영 안정성에서 Linux 우위
