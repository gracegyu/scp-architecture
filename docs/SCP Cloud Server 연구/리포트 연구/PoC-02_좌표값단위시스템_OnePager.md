**Technical Description**:

**현재 상황 분석**: 기존 시스템별 좌표 방식

- E2/E3 v4.0 이하: 0~1 범위 비율값 (용지 크기 대비)
- E3 v5.1 이상: mm 단위 실측값
- EzOrtho: mm 단위 (실제 파일 구조 확인 결과: 주석에 `<!-- unit : mm -->` 명시)
- 문제점: 비율값 기반의 한계(용지 변경 시 레이아웃 왜곡), 정밀도 부족(E3 RC v5.1: 1자리), 해상도별 불일치

**새로운 좌표 시스템 설계**:

```typescript
interface Coordinate {
  x: number // mm 단위, 소수점 3자리 정밀도
  y: number // mm 단위, 소수점 3자리 정밀도
  unit: 'mm' // 단위 명시
}

interface ViewportInfo {
  dpi: number // 화면 DPI
  paperSize: PaperSize // 용지 크기 정보
  scaleFactor: number // 화면 확대/축소 비율
}
```

**변환 알고리즘**:

1. **비율값 → 실측값 변환**:

   ```
   실측값(mm) = 비율값 × 용지크기(mm) - 여백(mm)
   ```

2. **화면 좌표 변환**:

   ```
   픽셀좌표 = (실측값 × DPI) / 25.4
   ```

3. **정밀도 보장**:
   - 소수점 3자리 (0.001mm = 1μm) 정밀도
   - IEEE 754 부동소수점 오차 고려한 반올림

**테스트 시나리오**:

1. **변환 정확성 테스트**:

   - E2 샘플 파일 50개 변환 후 역변환 비교
   - E3 v4.0/v5.1 파일 변환 정확도 검증
   - EzOrtho 차트 데이터 변환 무결성 확인

2. **해상도별 일관성 테스트**:

   - 72 DPI (웹 표준) vs 300 DPI (인쇄 표준)
   - 모바일 (160-480 DPI) vs 태블릿 vs 데스크톱
   - 4K, 8K 고해상도 디스플레이 대응

3. **용지 크기별 테스트**:
   - A3, A4, Letter, 의료용 특수 용지 크기
   - Portrait vs Landscape 방향
   - 사용자 정의 용지 크기 지원

**성능 기준**:

- **정밀도**: 기존 E3 RC v5.1 (1자리) 대비 100배 향상 (0.1mm → 0.001mm)
- **일관성**: 모든 해상도에서 ±0.1mm 이내 오차
- **성능**: 좌표 변환 시간 1ms 이내
- **호환성**: 100% 기존 데이터 변환 성공

#### 디자인 도구 좌표 시스템

**Figma (웹 기반 디자인 도구)**

- **좌표 단위**: 픽셀 (Pixel)
- **저장 형식**: JSON (실수값 좌표)
- **특징**:
  - 실수 기반 좌표 (소수점 지원)
  - 다양한 DPI 지원 (72 DPI ~ 300 DPI)
  - 화면/출력 일관성 유지
- **분석**: 웹 네이티브 환경에서 실수 좌표 시스템 성공 사례

**Adobe XD (디자인 도구)**

- **좌표 단위**: 픽셀 (Pixel)
- **저장 형식**: JSON (실수값 좌표)
- **특징**:
  - 정밀한 실수 좌표 시스템
  - 반응형 디자인 지원
  - 다양한 해상도 대응
- **분석**: 복잡한 레이아웃도 실수 좌표로 정확하게 표현

**Sketch (디자인 도구)**

- **좌표 단위**: 포인트 (Point, 72 DPI 기준)
- **저장 형식**: JSON (실수값 좌표)
- **특징**:
  - 실수 기반 좌표
  - @1x, @2x, @3x 등 다양한 배율 지원
  - 정밀한 레이아웃 제어
- **분석**: 절대 단위(포인트) 기반 실수 좌표 시스템

#### 문서/프레젠테이션 도구 좌표 시스템

**Notion (노트/프로젝트 관리)**

- **좌표 단위**: 픽셀 (실제 저장은 블록 기반)

  - 블록 기반 레이아웃 (간접적 좌표)

- **좌표 단위**: 포인트 (Point, 72 DPI 기준)

- **특징**:
  - 실수 기반 좌표
  - 다양한 용지 크기 지원
  - 인쇄/화면 일관성

#### 의료 이미지 뷰어 좌표 시스템

**DICOM 표준 (의료 이미지 표준)**

- **좌표 단위**: mm (실제 물리적 크기)
- **특징**:
  - 실수 기반 물리적 좌표
  - 고해상도 의료 이미지 지원
  - 측정값 정밀도 중요 (1mm 이하)
- **분석**: 의료 분야에서 mm 기반 실수 좌표가 표준

**PACS 시스템 (Picture Archiving and Communication System)**

- **좌표 단위**: mm 또는 픽셀 (실수값)
- **특징**:
  - 실수 기반 좌표
  - 다양한 해상도/크기 이미지 지원
  - 측정값 정밀도 보장
- **분석**: 의료 이미지 뷰어에서 실수 좌표 필수

#### 그래픽 편집 도구 좌표 시스템

**Canvas API (HTML5)**

- **좌표 단위**: 픽셀 (실수값 지원)
- **특징**:
  - 실수 기반 좌표 (부동소수점)
  - 고해상도 디스플레이 지원 (devicePixelRatio)
  - 정밀한 그래픽 제어
- **분석**: 웹 표준에서도 실수 좌표 지원

**SVG (Scalable Vector Graphics)**

- **좌표 단위**: 사용자 단위 (기본 픽셀, viewBox로 스케일링)
- **특징**:
  - 실수 기반 좌표
  - 벡터 그래픽으로 확대/축소 시 정밀도 유지
  - 다양한 단위 지원 (px, mm, cm, in 등)
- **분석**: 벡터 그래픽에서 실수 좌표로 정밀도 보장

**주요 인사이트**:

1. **실수 좌표는 표준**: 모든 주요 도구가 실수 좌표 사용 (우리 제품도 모두 실수 사용)
2. **절대 단위 선호**: 픽셀, 포인트, mm 등 절대 단위 사용 (비율값 제한적)
3. **JSON 저장 형식**: 웹 기반 도구는 JSON으로 실수 좌표 저장
4. **다양한 DPI 대응**: 실수 좌표로 다양한 해상도 일관성 유지
5. **정밀도 중요**: 의료/디자인 분야에서 정밀도가 핵심 요구사항

**우리 선택의 타당성**:

- mm 기반 실수 좌표는 의료 표준(DICOM)과 일치

- 디자인 도구들(Figma, Adobe XD)과 유사한 접근 방식
- 다양한 해상도 대응은 업계 표준 관행
