# PoC-03 결과 보고서: DPI 및 렌더링 전략 결정

## 1. 개요

### 1.1 검증 목표

화면 표시, 프린트, 폰트 처리 시 발생하는 72 DPI, 96 DPI, 300 DPI 등의 복잡한 관계를 정리하고, px, pt 단위 사용 및 PDF 프린트 방안을 포함한 최적의 하나의 통합 렌더링 전략을 결정합니다. PoC-02에서 결정한 mm 좌표계와 완벽하게 통합되도록 폰트 크기, 좌표 변환, 인쇄 품질을 일관되게 처리하는 방안을 수립합니다.

### 1.2 DPI의 의미 구분

문서에서 언급되는 72 DPI, 96 DPI, 300 DPI는 각각 다른 의미를 가집니다. 이 구분을 명확히 이해하는 것이 중요합니다:

| DPI | 의미 | 역할 | 변경 가능 여부 | 사용 시점 |
|-----|------|------|---------------|----------|
| **72 DPI** | Point 단위의 정의 기준 | 단위 정의 (1 inch = 72 points) | ❌ 불가능 (단위 정의) | Point 정의 |
| **96 DPI** | 웹 브라우저 CSS 픽셀 계산 기준 | CSS 픽셀 단위 계산 표준 | ❌ 불가능 (웹 표준) | 화면 렌더링 |
| **300 DPI** | 실제 프린터의 물리적 해상도 | 프린터의 실제 인쇄 능력 | ✅ 가능 (프린터에 따라 다름) | 인쇄 |

**1. 72 DPI: Point 단위의 정의 기준**

- **의미**: Point (pt) 단위가 정의되는 기준
- **정의**: 1 inch = 72 points (Point 단위의 수학적 정의)
- **역할**: 단위 정의이지, 실제 화면이나 프린터의 해상도가 아님

**역사적 배경**:
- **유래**: 초기 매킨토시(Macintosh) 컴퓨터의 디스플레이가 인치당 72픽셀을 가졌던 것에서 유래
- **관습**: 포토샵 등 디자인 툴에서 '웹용 저장'을 할 때 기본 설정으로 오랫동안 사용되어 온 수치
- **현재**: 많은 디자이너들이 웹 이미지를 제작할 때 여전히 72 DPI를 기준으로 삼음
- **Point 단위**: 인쇄용 단위로 72 DPI 기준으로 정의됨 (1 inch = 72 points)

- **특징**:
  - Point는 물리적 크기가 고정된 절대 단위
  - 1 pt = 1/72 inch = 25.4/72 mm ≈ 0.3528 mm (항상 동일)
  - 프린터 DPI와 무관하게 항상 동일한 물리적 크기
- **예시**: 
  - 12pt 텍스트는 어떤 프린터에서도 4.233mm 높이
  - "72 DPI 기준"이라는 표현은 "1 inch = 72 points"라는 단위 정의를 의미

**2. 96 DPI: 웹 브라우저 CSS 픽셀 계산 기준**

- **의미**: 웹 브라우저가 CSS 픽셀 단위를 계산할 때 사용하는 표준
- **정의**: 1 inch = 96 CSS pixels (웹 표준)
- **역할**: CSS에서 `px` 단위를 해석할 때 사용하는 기준

**역사적 배경**:
- **유래**: 윈도우(Windows) 기반 PC들이 대중화되면서 인치당 96픽셀을 표준으로 삼음
- **CSS 규격**: W3C의 CSS 명세에서 1인치(1in)는 정확히 96px로 정의됨
- **표준 수식**: 1 CSS inch = 96 CSS pixels
- **현재**: 모든 웹 브라우저가 96 DPI 기준으로 CSS 픽셀을 계산하는 것이 웹 표준

- **특징**:
  - 실제 화면의 물리적 DPI와는 다를 수 있음
  - 모든 웹 브라우저가 96 DPI 기준으로 CSS 픽셀을 계산
  - 화면 표시 시 일관된 크기 보장
- **예시**: 
  - CSS `font-size: 12pt` → 브라우저가 96 DPI 기준으로 해석 → 16px
  - 실제 화면이 144 DPI (Retina)여도 CSS는 96 DPI 기준으로 계산
  - 화면 렌더링 시 항상 96 DPI 기준 사용

**3. 300 DPI: 실제 프린터의 물리적 해상도**

- **의미**: 실제 프린터가 인쇄할 때 사용하는 물리적 해상도
- **정의**: 1 inch당 300개의 점(dot)을 출력할 수 있는 능력
- **역할**: 인쇄 품질 결정 (해상도가 높을수록 선명함)
- **특징**:
  - 프린터마다 다름 (150 DPI, 300 DPI, 600 DPI, 1200 DPI 등)
  - 의료 인쇄 표준으로 자주 사용됨
  - 인쇄 시 실제 픽셀 수 결정
- **예시**:
  - 4.233mm (12pt)를 300 DPI로 인쇄 → 50px 사용
  - 같은 크기를 600 DPI로 인쇄 → 100px 사용 (더 선명하지만 물리적 크기는 동일)

**핵심 차이점**:

1. **72 DPI vs 300 DPI**:
   - 72 DPI: Point 단위의 정의 (변경 불가능, 단위 정의)
   - 300 DPI: 프린터의 실제 능력 (프린터마다 다름, 물리적 해상도)
   - Point(72 DPI 정의)를 300 DPI 프린터로 인쇄 가능

2. **96 DPI vs 300 DPI**:
   - 96 DPI: 웹 브라우저 CSS 계산 기준 (화면 표시용)
   - 300 DPI: 실제 프린터 해상도 (인쇄용)
   - 화면에서는 96 DPI 기준, 인쇄에서는 프린터 DPI 사용

3. **왜 혼동되는가?**:
   - "72 DPI 기준"이라는 표현이 실제 해상도처럼 들릴 수 있음
   - 하지만 72 DPI는 단위 정의일 뿐, 실제 해상도가 아님
   - Point는 72 DPI로 정의되지만, 실제 렌더링은 화면(96 DPI)과 프린터(300 DPI 등)의 실제 DPI 사용

**실제 동작 예시**:

**시나리오**: 12pt 폰트를 화면에 표시하고 300 DPI 프린터로 인쇄

1. **Point 정의 (72 DPI 기준)**:
   - 12pt = 12 × (1/72 inch) = 4.233mm
   - 이것은 Point 단위의 정의이므로 변하지 않음

2. **화면 렌더링 (96 DPI 기준)**:
   - 브라우저가 12pt를 96 DPI 기준으로 해석
   - 12pt × (96/72) = 16px
   - 물리적 크기: 16px × (25.4/96) = 4.233mm ✅

3. **프린트 렌더링 (300 DPI 프린터)**:
   - 브라우저가 12pt를 프린터 DPI에 맞춰 변환
   - 12pt × (300/72) = 50px
   - 물리적 크기: 50px × (25.4/300) = 4.233mm ✅

**Point → mm 변환과 CSS 96 DPI의 관계**:

**질문**: Point → mm 변환은 72 DPI 기준인데, CSS는 96 DPI 표준인데 어떻게 일치하나요?

**답변**: Point → mm 변환은 항상 72 DPI 기준이지만, CSS에서 Point를 화면에 표시할 때는 96 DPI 기준으로 픽셀로 변환합니다. 하지만 **최종 물리적 크기(mm)는 동일**합니다.

**수학적 검증**:

**1단계: Point → mm 변환 (72 DPI 기준, 단위 정의)**:
```
12pt → mm: 12 × (25.4/72) = 4.233mm
```
- 이것은 Point 단위의 정의이므로 항상 동일
- 72 DPI는 단위 정의일 뿐, 실제 해상도가 아님

**2단계: CSS에서 Point → Pixel 변환 (96 DPI 기준, 화면 표시)**:
```
12pt → CSS px (96 DPI): 12 × (96/72) = 16px
```
- 브라우저가 CSS `font-size: 12pt`를 96 DPI 기준으로 해석
- 96 DPI는 웹 브라우저 CSS 픽셀 계산 기준

**3단계: CSS Pixel → mm 변환 (96 DPI 기준, 물리적 크기 확인)**:
```
16px (96 DPI) → mm: 16 × (25.4/96) = 4.233mm ✅
```
- 최종 물리적 크기는 4.233mm로 동일!

**결과 비교**:

| 변환 경로 | 계산 과정 | 최종 물리적 크기 | 일치 여부 |
|---------|----------|----------------|----------|
| **직접 변환** | 12pt → mm (72 DPI 정의) | 4.233mm | ✅ |
| **CSS 경유** | 12pt → 16px (96 DPI) → mm | 4.233mm | ✅ 완벽 일치 |

**핵심 원리**:

1. **Point → mm**: 항상 72 DPI 기준 (단위 정의)
   - `mm = pt × (25.4/72)`
   - 이것은 Point 단위의 수학적 정의

2. **CSS Point → Pixel**: 96 DPI 기준 (웹 표준)
   - `px = pt × (96/72)`
   - 브라우저가 CSS에서 Point를 픽셀로 변환할 때 사용

3. **CSS Pixel → mm**: 96 DPI 기준 (물리적 크기 확인)
   - `mm = px × (25.4/96)`
   - 최종 물리적 크기 계산

4. **최종 결과**: 
   - `pt × (96/72) × (25.4/96) = pt × (25.4/72) = mm` ✅
   - 96/72와 25.4/96을 곱하면 25.4/72가 되어, 직접 변환과 동일!

**왜 이렇게 복잡한가?**:

- **역사적 이유**: 
  - Point는 인쇄용 단위로 72 DPI 기준으로 정의됨 (초기 매킨토시 디스플레이에서 유래)
  - 포토샵 등 디자인 툴에서 오랫동안 72 DPI를 관습적으로 사용
- **웹 표준**: 
  - 윈도우 PC 대중화로 96 DPI가 표준화됨
  - W3C CSS 명세에서 1 inch = 96px로 정의됨
  - 모든 웹 브라우저가 96 DPI 기준으로 CSS 픽셀을 계산
- **결과**: 두 기준이 다르지만, 수학적으로 최종 물리적 크기는 동일하게 계산됨

**실제 사용**:

- **Point → mm 변환**: 72 DPI 기준 사용 (단위 정의)
- **CSS 렌더링**: 브라우저가 자동으로 96 DPI 기준으로 처리
- **최종 결과**: 물리적 크기(mm)는 항상 동일하므로 mm 좌표계와 완벽하게 일치

**결론**: 
- Point는 72 DPI로 정의되지만, 실제 렌더링은 화면(96 DPI)과 프린터(300 DPI 등)의 실제 DPI에 맞춰 변환됨
- 최종 물리적 크기(mm)는 항상 동일하므로, mm 좌표계와 완벽하게 일치

## 3. 최종 전략 상세

### 3.1 Item 1: 화면 렌더링 DPI 전략

**선정**: **96 DPI 고정 (웹 표준)**

**선정 근거**:
- 간단하고 예측 가능한 동작
- 모든 브라우저에서 일관된 동작
- 추가 DPI 감지 로직 불필요 (개발 복잡도 최소화)
- 고해상도 디스플레이에서 작게 보일 수 있으나, 의료 리포트는 정확도가 우선

**구현 방법**:
```css
/* 화면 렌더링: 96 DPI 기준 */
@media screen {
  .report-container {
    /* mm 좌표를 96 DPI 기준 픽셀로 변환 */
    /* 1 mm = 3.78 px (96 DPI 기준) */
  }
}
```

**제외된 옵션**: 동적 DPI 감지
- 이유: 복잡도 증가, 브라우저별 차이 가능성, 개발 비용 증가

---

### 3.2 Item 2: 프린트 렌더링 DPI 전략

**선정**: **CSS pt 단위 사용 (브라우저 자동 변환)**

**선정 근거**:
- 브라우저가 자동으로 프린터 DPI에 맞춰 변환 (개발 복잡도 최소화)
- 추가 JavaScript 변환 로직 불필요
- 인쇄 시 정확한 물리적 크기 보장
- 웹 표준 준수

**구현 방법**:
```css
/* 프린트 렌더링: CSS pt 단위 사용 */
@media print {
  .text-element {
    font-size: 12pt;  /* 브라우저가 프린터 DPI에 맞춰 자동 변환 */
  }
  
  .report-container {
    /* mm 좌표는 그대로 사용, 브라우저가 자동 변환 */
    width: 210mm;  /* A4 가로 */
    height: 297mm; /* A4 세로 */
  }
}
```

**제외된 옵션**:
- `@media print` + 300 DPI 가정 (수동 변환): 복잡도 증가, 실제 프린터 DPI와 다를 수 있음
- 사용자 설정 옵션: 사용자 부담 증가, 복잡도 증가

---

### 3.3 Item 3: 폰트 단위 선택

**선정**: **pt (Point) 단위 사용**

**선정 근거**:
- PoC-02 Q&A 섹션에서 권장된 단위
- 브라우저가 자동으로 DPI에 맞춰 변환 (화면 96 DPI, 프린트 프린터 DPI)
- mm 좌표계와 물리적 크기 일치 가능 (1 pt = 25.4/72 mm ≈ 0.3528 mm)
- 웹 표준 및 의료 인쇄 표준 준수
- 개발 복잡도 최소화 (CSS `font-size: 12pt` 직접 사용)
- **폰트 크기의 표준 단위로 널리 사용됨** (일반적이고 검증된 관행)

**mm 좌표계와의 통합**:
- 수학적 관계: 1 pt = 25.4/72 mm ≈ 0.3528 mm
- 화면 렌더링: 12pt → 16px (96 DPI) → 4.233mm ✅
- 프린트 렌더링: 12pt → 4.233mm (72 DPI 기준) ✅
- **결론**: Point와 mm 좌표계는 수학적으로 완벽하게 일치

**구현 예시**:
```typescript
interface TextElement {
  position: { x: 26.25, y: 74.25, unit: 'mm' },
  style: {
    fontSize: 12,  // pt 단위
    fontFamily: 'Arial'
  },
  content: '<p>의료 리포트 텍스트</p>'
}
```

```css
.text-element {
  position: absolute;
  left: 26.25mm;  /* mm 좌표 */
  top: 74.25mm;   /* mm 좌표 */
  font-size: 12pt; /* pt 폰트 크기 */
}
```

**제외된 옵션**:

1. **mm 단위**:
   - 기술적으로는 가능하나 **폰트 크기 단위로 일반적이지 않음**
   - CSS 표준에서 폰트 크기는 pt, px, em, rem 등이 권장됨
   - 브라우저 호환성 및 동작 방식이 pt 대비 덜 검증됨
   - 개발자 및 디자이너에게 혼란 가능 (폰트 크기를 mm로 지정하는 것은 비표준)
   - 좌표 단위와 통일성을 위해 고려했으나, 표준 관행을 따르는 것이 더 중요

2. **px 단위**:
   - DPI별로 다른 값 계산 필요, 복잡도 증가
   - 인쇄 시 물리적 크기 보장 불가

3. **하이브리드 (pt + px)**:
   - 복잡도 증가, 두 가지 단위 관리 필요

---

### 3.4 Item 4: 미디어 쿼리 전략

**선정**: **@media screen과 @media print 분리**

**선정 근거**:
- 화면과 프린트를 명확히 분리하여 각각 최적화 가능
- CSS만으로 처리 가능 (JavaScript 불필요)
- 개발 복잡도 최소화
- 유지보수 용이

**구현 방법**:
```css
/* 화면 렌더링 */
@media screen {
  .report-container {
    /* 96 DPI 기준 렌더링 */
    width: 210mm;
    height: 297mm;
  }
  
  .text-element {
    font-size: 12pt;  /* 브라우저가 96 DPI 기준으로 변환 */
  }
}

/* 프린트 렌더링 */
@media print {
  .report-container {
    /* mm 단위 그대로 사용, 브라우저가 프린터 DPI에 맞춰 변환 */
    width: 210mm;
    height: 297mm;
  }
  
  .text-element {
    font-size: 12pt;  /* 브라우저가 프린터 DPI에 맞춰 변환 */
  }
}
```

**제외된 옵션**: 단일 스타일 + JavaScript 동적 변환
- 이유: JavaScript 복잡도 증가, 개발 비용 증가

### 3.5 Item 5: PDF 생성 전략

**선정 근거**:
- 개발 복잡도 최소화 (기본 기능은 브라우저 프린트 사용)
- 대부분의 사용자는 브라우저 프린트로 충분
- 고품질이 필요한 경우에만 PDF 생성 제공
- 서버 인프라 비용 절감

**구현 방법**:
1. **기본 인쇄**: 브라우저 프린트 사용

   function printReport() {

**참고**: PDF 생성 라이브러리 평가 및 선택은 PoC-10에서 수행합니다.

### 3.6 Item 6: mm 좌표계 통합 전략

**선정**: **pt와 mm의 수학적 관계 활용**

**통합 원리**:
- mm 좌표계: 물리적 크기 보장
- pt 폰트 단위: 물리적 크기 보장
- 수학적 관계: 1 pt = 25.4/72 mm ≈ 0.3528 mm

**검증 결과** (이론적 분석):

| Point | mm (이론) | 화면 Pixel (96 DPI) | 화면 mm (96 DPI) | 인쇄 mm (72 DPI) | 일치 여부 |
|-------|----------|-------------------|-----------------|-----------------|----------|
| 12pt  | 4.233mm  | 16px              | 4.233mm         | 4.233mm         | ✅ 완벽 일치 |
| 10pt  | 3.528mm  | 13.33px           | 3.528mm         | 3.528mm         | ✅ 완벽 일치 |
| 14pt  | 4.939mm  | 18.67px           | 4.939mm         | 4.939mm         | ✅ 완벽 일치 |

**결론**: Point와 mm 좌표계는 수학적으로 완벽하게 일치하므로, 별도의 변환 로직 없이 CSS에서 직접 사용 가능합니다.

4. **표준 준수**: 웹 표준 및 의료 인쇄 표준 준수

### 4.2 구현 가이드라인

**좌표 및 폰트 크기 지정**:
```typescript
interface Element {
  position: { x: number, y: number, unit: 'mm' },
  size: { width: number, height: number, unit: 'mm' },

  }

```

**CSS 렌더링**:
```css

    /* 추가 스타일 필요 시 */
  }

/* 프린트 렌더링 (프린터 DPI) */
@media print {
  .element {
    /* 추가 스타일 필요 시 */
  }
}
```

**JavaScript 변환 함수** (참고용, 실제로는 CSS에서 자동 처리):
```typescript
/**
 * mm를 픽셀로 변환 (화면 렌더링용, 96 DPI 기준)
 */
function mmToPx(mm: number, dpi: number = 96): number {
  return (mm * dpi) / 25.4
}

/**
 * pt를 픽셀로 변환 (참고용, 실제로는 CSS에서 자동 처리)
 */
function ptToPx(pt: number, dpi: number): number {
  return (pt * dpi) / 72
}
```

**실제 구현 시 주의사항**:
- CSS에서 mm와 pt 단위를 직접 사용하면 브라우저가 자동으로 변환
- JavaScript 변환 함수는 필요 시에만 사용 (대부분 CSS로 처리 가능)
- 미디어 쿼리로 화면과 프린트를 분리하여 각각 최적화
