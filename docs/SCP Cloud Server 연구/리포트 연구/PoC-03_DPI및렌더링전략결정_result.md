# PoC-03 결과 보고서: DPI 및 렌더링 전략 결정

## 1. 개요

### 1.1 검증 목표

화면 표시, 프린트, 폰트 처리 시 발생하는 72 DPI, 96 DPI, 300 DPI 등의 복잡한 관계를 정리하고, px, pt 단위 사용 및 PDF 프린트 방안을 포함한 최적의 하나의 통합 렌더링 전략을 결정합니다. PoC-02에서 결정한 mm 좌표계와 완벽하게 통합되도록 폰트 크기, 좌표 변환, 인쇄 품질을 일관되게 처리하는 방안을 수립합니다.

### 1.2 DPI의 의미 구분: 논리적 DPI vs 물리적 DPI

DPI는 **논리적 DPI**와 **물리적 DPI**로 구분됩니다. 이 구분을 명확히 이해하는 것이 핵심입니다:

**4가지 DPI 영역**:

| 영역 | DPI 값 | 의미 | 변경 가능 여부 | 개발 시 고려 |
|------|--------|------|---------------|------------|
| **웹 논리 DPI** | **96 DPI** | CSS Pixel 계산 기준 (웹 표준) | ❌ 고정 (웹 표준) | ✅ **논리만 신경쓰면 됨** |
| **웹 물리 DPI** | 96, 144, 192 등 | 실제 모니터의 물리적 해상도 | ✅ 모니터마다 다름 | ❌ 신경쓸 필요 없음 (브라우저가 자동 처리) |
| **프린터 논리 DPI** | **72 DPI** | Point 단위 정의 기준 (1 inch = 72 points) | ❌ 고정 (단위 정의) | ✅ **논리만 신경쓰면 됨** |
| **프린터 물리 DPI** | 300, 600, 1200 등 | 실제 프린터의 물리적 해상도 | ✅ 프린터마다 다름 | ❌ 신경쓸 필요 없음 (브라우저가 자동 변환) |

**핵심 원리**:

1. **논리적 DPI는 고정**: 72 DPI (Point 정의), 96 DPI (CSS Pixel 기준)
2. **물리적 DPI는 가변**: 모니터/프린터마다 다름
3. **개발자는 논리적 DPI만 고려**: 물리적 DPI는 브라우저/프린터가 자동 처리
4. **결과**: 물리적 크기(mm)는 항상 동일하게 보장됨

**상세 설명**:

**1. 웹 논리 DPI (96 DPI)**:
- **의미**: CSS Pixel 계산 기준 (웹 표준)
- **정의**: 1 inch = 96 CSS pixels
- **역할**: 브라우저가 CSS `px` 단위를 해석할 때 사용하는 고정 기준
- **특징**: 
  - 모든 웹 브라우저가 96 DPI 기준으로 계산 (웹 표준)
  - 실제 모니터의 물리적 DPI와 무관 (144 DPI Retina 모니터여도 CSS는 96 DPI 기준)
  - 개발자는 96 DPI만 고려하면 됨
- **예시**: `font-size: 12pt` → 브라우저가 96 DPI 기준으로 16px로 변환

**2. 웹 물리 DPI (모니터마다 다름)**:
- **의미**: 실제 모니터의 물리적 해상도
- **값**: 96 DPI, 144 DPI (Retina), 192 DPI 등 모니터마다 다름
- **역할**: 브라우저가 device pixel ratio로 자동 처리
- **특징**: 개발자가 신경쓸 필요 없음 (브라우저가 자동 처리)

**3. 프린터 논리 DPI (72 DPI)**:
- **의미**: Point 단위 정의 기준
- **정의**: 1 inch = 72 points (단위 정의)
- **역할**: Point 단위의 수학적 정의 (실제 해상도 아님)
- **특징**:
  - Point는 물리적 크기가 고정된 절대 단위
  - 1 pt = 1/72 inch = 25.4/72 mm ≈ 0.3528 mm (항상 동일)
  - 개발자는 72 DPI만 고려하면 됨
- **예시**: 12pt 텍스트는 어떤 프린터에서도 4.233mm 높이

**4. 프린터 물리 DPI (프린터마다 다름)**:
- **의미**: 실제 프린터의 물리적 해상도
- **값**: 300 DPI, 600 DPI, 1200 DPI 등 프린터마다 다름
- **역할**: 인쇄 품질 결정 (해상도가 높을수록 선명함)
- **특징**: 개발자가 신경쓸 필요 없음 (브라우저가 프린터 DPI에 맞춰 자동 변환)

**핵심 정리**:

- **논리적 DPI (고정)**: 72 DPI (Point 정의), 96 DPI (CSS Pixel 기준) → 개발자가 고려해야 함
- **물리적 DPI (가변)**: 모니터/프린터마다 다름 → 브라우저/프린터가 자동 처리
- **개발 원칙**: 논리적 DPI만 신경쓰면 됨, 물리적 DPI는 무시해도 됨
- **결과**: 물리적 크기(mm)는 항상 동일하게 보장됨

**실제 동작 예시**:

**시나리오**: 12pt 폰트를 화면에 표시하고 300 DPI 프린터로 인쇄

| 단계 | DPI 기준 | 계산 | 물리적 크기 |
|------|---------|------|------------|
| **1. Point 정의** | 논리적 72 DPI | 12pt = 12 × (1/72 inch) = 4.233mm | 4.233mm ✅ |
| **2. 화면 렌더링** | 논리적 96 DPI | 12pt → 16px (96 DPI) → 4.233mm | 4.233mm ✅ |
| **3. 프린트 렌더링** | 논리적 72 DPI → 물리적 300 DPI | 12pt → 50px (300 DPI) → 4.233mm | 4.233mm ✅ |

**핵심**: 논리적 DPI(72, 96)만 고려하면 되고, 물리적 DPI(300 등)는 브라우저가 자동 처리하여 최종 물리적 크기는 항상 동일합니다.

**수학적 검증**:

- **Point → mm (논리적 72 DPI)**: `12pt × (25.4/72) = 4.233mm`
- **Point → Pixel (논리적 96 DPI)**: `12pt × (96/72) = 16px`
- **Pixel → mm (논리적 96 DPI)**: `16px × (25.4/96) = 4.233mm` ✅

**결론**: 
- 논리적 DPI(72, 96)만 고려하면 됨
- 물리적 DPI는 브라우저/프린터가 자동 처리
- 최종 물리적 크기(mm)는 항상 동일하므로 mm 좌표계와 완벽하게 일치

## 3. 최종 전략 상세

### 3.1 Item 1: 화면 렌더링 DPI 전략

**선정**: **96 DPI 고정 (웹 표준)**

**선정 근거**:
- 간단하고 예측 가능한 동작
- 모든 브라우저에서 일관된 동작
- 추가 DPI 감지 로직 불필요 (개발 복잡도 최소화)
- 고해상도 디스플레이에서 작게 보일 수 있으나, 의료 리포트는 정확도가 우선

**구현 방법**:
```css
/* 화면 렌더링: 96 DPI 기준 */
@media screen {
  .report-container {
    /* mm 좌표를 96 DPI 기준 픽셀로 변환 */
    /* 1 mm = 3.78 px (96 DPI 기준) */
  }
}
```

**제외된 옵션**: 동적 DPI 감지
- 이유: 복잡도 증가, 브라우저별 차이 가능성, 개발 비용 증가

---

### 3.2 Item 2: 프린트 렌더링 DPI 전략

**선정**: **CSS pt 단위 사용 (브라우저 자동 변환)**

**선정 근거**:
- 브라우저가 자동으로 프린터 DPI에 맞춰 변환 (개발 복잡도 최소화)
- 추가 JavaScript 변환 로직 불필요
- 인쇄 시 정확한 물리적 크기 보장
- 웹 표준 준수

**구현 방법**:
```css
/* 프린트 렌더링: CSS pt 단위 사용 */
@media print {
  .text-element {
    font-size: 12pt;  /* 브라우저가 프린터 DPI에 맞춰 자동 변환 */
  }
  
  .report-container {
    /* mm 좌표는 그대로 사용, 브라우저가 자동 변환 */
    width: 210mm;  /* A4 가로 */
    height: 297mm; /* A4 세로 */
  }
}
```

**제외된 옵션**:
- `@media print` + 300 DPI 가정 (수동 변환): 복잡도 증가, 실제 프린터 DPI와 다를 수 있음
- 사용자 설정 옵션: 사용자 부담 증가, 복잡도 증가

---

### 3.3 Item 3: 폰트 단위 선택

**선정**: **pt (Point) 단위 사용**

**선정 근거**:
- PoC-02 Q&A 섹션에서 권장된 단위
- 브라우저가 자동으로 DPI에 맞춰 변환 (화면 96 DPI, 프린트 프린터 DPI)
- mm 좌표계와 물리적 크기 일치 가능 (1 pt = 25.4/72 mm ≈ 0.3528 mm)
- 웹 표준 및 의료 인쇄 표준 준수
- 개발 복잡도 최소화 (CSS `font-size: 12pt` 직접 사용)
- **폰트 크기의 표준 단위로 널리 사용됨** (일반적이고 검증된 관행)

**mm 좌표계와의 통합**:
- 수학적 관계: 1 pt = 25.4/72 mm ≈ 0.3528 mm
- 화면 렌더링: 12pt → 16px (96 DPI) → 4.233mm ✅
- 프린트 렌더링: 12pt → 4.233mm (72 DPI 기준) ✅
- **결론**: Point와 mm 좌표계는 수학적으로 완벽하게 일치

**구현 예시**:
```typescript
interface TextElement {
  position: { x: 26.25, y: 74.25, unit: 'mm' },
  style: {
    fontSize: 12,  // pt 단위
    fontFamily: 'Arial'
  },
  content: '<p>의료 리포트 텍스트</p>'
}
```

```css
.text-element {
  position: absolute;
  left: 26.25mm;  /* mm 좌표 */
  top: 74.25mm;   /* mm 좌표 */
  font-size: 12pt; /* pt 폰트 크기 */
}
```

**제외된 옵션**:

1. **mm 단위**:
   - 기술적으로는 가능하나 **폰트 크기 단위로 일반적이지 않음**
   - CSS 표준에서 폰트 크기는 pt, px, em, rem 등이 권장됨
   - 브라우저 호환성 및 동작 방식이 pt 대비 덜 검증됨
   - 개발자 및 디자이너에게 혼란 가능 (폰트 크기를 mm로 지정하는 것은 비표준)
   - 좌표 단위와 통일성을 위해 고려했으나, 표준 관행을 따르는 것이 더 중요

2. **px 단위**:
   - DPI별로 다른 값 계산 필요, 복잡도 증가
   - 인쇄 시 물리적 크기 보장 불가

3. **하이브리드 (pt + px)**:
   - 복잡도 증가, 두 가지 단위 관리 필요

### 3.4 Item 4: 미디어 쿼리 전략

**선정**: **@media screen과 @media print 분리**

**선정 근거**:
- 화면과 프린트를 명확히 분리하여 각각 최적화 가능
- CSS만으로 처리 가능 (JavaScript 불필요)
- 개발 복잡도 최소화
- 유지보수 용이

**구현 방법**:
```css
/* 화면 및 프린트 공통 스타일 (브라우저가 자동으로 다르게 처리) */
.report-container {
  width: 210mm;
  height: 297mm;
}

.text-element {
  font-size: 12pt;  /* 브라우저가 화면에서는 96 DPI, 프린트에서는 프린터 DPI로 자동 변환 */
}

/* 필요 시 미디어별 추가 스타일 */
@media screen {
  /* 화면 전용 스타일 (예: 배경색, 스크롤 등) */
}

@media print {
  /* 프린트 전용 스타일 (예: 페이지 브레이크, 배경 제거 등) */
  .report-container {
    page-break-after: avoid;
  }
}
```

**핵심**: CSS 코드는 동일하지만, 브라우저가 `@media screen`일 때는 96 DPI 기준으로, `@media print`일 때는 프린터 DPI 기준으로 자동 변환합니다.

**제외된 옵션**: 단일 스타일 + JavaScript 동적 변환
- 이유: JavaScript 복잡도 증가, 개발 비용 증가

### 3.5 Item 5: PDF 생성 전략

**선정**: **선택적 (브라우저 프린트 기본, 고품질 필요 시 PDF)**

**선정 근거**:
- 개발 복잡도 최소화 (기본 기능은 브라우저 프린트 사용)
- 대부분의 사용자는 브라우저 프린트로 충분
- 고품질이 필요한 경우에만 PDF 생성 제공
- 서버 인프라 비용 절감

**구현 방법**:
1. **기본 인쇄**: 브라우저 프린트 사용
   ```typescript
   function printReport() {
     window.print();  // 브라우저 프린트 다이얼로그
   }
   ```

2. **고품질 PDF 생성** (선택적, 향후 구현):
   - 클라이언트 사이드: jsPDF 또는 React-PDF (PoC-10에서 평가)
   - 서버 사이드: Puppeteer 또는 PDFKit (PoC-10에서 평가)
   - 사용자가 "고품질 PDF 다운로드" 옵션 선택 시에만 제공

**제외된 옵션**:
- PDF 생성 필수: 개발 복잡도 증가, 서버 인프라 비용 증가
- 하이브리드 방식: 두 가지 방식 유지 필요, 복잡도 증가

**참고**: PDF 생성 라이브러리 평가 및 선택은 PoC-10에서 수행합니다.

### 3.6 Item 6: mm 좌표계 통합 전략

**선정**: **pt와 mm의 수학적 관계 활용**

**통합 원리**:
- mm 좌표계: 물리적 크기 보장
- pt 폰트 단위: 물리적 크기 보장
- 수학적 관계: 1 pt = 25.4/72 mm ≈ 0.3528 mm

**검증 결과** (이론적 분석):

| Point | mm (이론) | 화면 Pixel (96 DPI) | 화면 mm (96 DPI) | 인쇄 mm (72 DPI) | 일치 여부 |
|-------|----------|-------------------|-----------------|-----------------|----------|
| 12pt  | 4.233mm  | 16px              | 4.233mm         | 4.233mm         | ✅ 완벽 일치 |
| 10pt  | 3.528mm  | 13.33px           | 3.528mm         | 3.528mm         | ✅ 완벽 일치 |
| 14pt  | 4.939mm  | 18.67px           | 4.939mm         | 4.939mm         | ✅ 완벽 일치 |

**결론**: Point와 mm 좌표계는 수학적으로 완벽하게 일치하므로, 별도의 변환 로직 없이 CSS에서 직접 사용 가능합니다.

## 4. 통합 전략 요약

### 4.1 핵심 원칙

1. **간단함**: 브라우저 표준 기능 활용, 최소한의 코드로 구현
2. **정확도**: 인쇄 시 실제 물리적 크기 보장
3. **일관성**: 화면과 프린트에서 동일한 물리적 크기 유지
4. **표준 준수**: 웹 표준 및 의료 인쇄 표준 준수

### 4.2 구현 가이드라인

**좌표 및 폰트 크기 지정**:
```typescript
interface Element {
  position: { x: number, y: number, unit: 'mm' },
  size: { width: number, height: number, unit: 'mm' },
  style: {
    fontSize: number,  // pt 단위
    fontFamily: string
  }
}
```

**CSS 렌더링**:
```css
/* 화면 및 프린트 공통 */
.element {
  position: absolute;
  left: 26.25mm;   /* mm 좌표 */
  top: 74.25mm;     /* mm 좌표 */
  width: 50mm;      /* mm 크기 */
  height: 20mm;     /* mm 크기 */
  font-size: 12pt;  /* pt 폰트 크기 */
}

/* 화면 렌더링 (96 DPI) */
@media screen {
  .element {
    /* 추가 스타일 필요 시 */
  }
}

/* 프린트 렌더링 (프린터 DPI) */
@media print {
  .element {
    /* 추가 스타일 필요 시 */
  }
}
```

**JavaScript 변환 함수** (참고용, 실제로는 CSS에서 자동 처리):
```typescript
/**
 * mm를 픽셀로 변환 (화면 렌더링용, 96 DPI 기준)
 */
function mmToPx(mm: number, dpi: number = 96): number {
  return (mm * dpi) / 25.4
}

/**
 * pt를 픽셀로 변환 (참고용, 실제로는 CSS에서 자동 처리)
 */
function ptToPx(pt: number, dpi: number): number {
  return (pt * dpi) / 72
}
```

**실제 구현 시 주의사항**:
- CSS에서 mm와 pt 단위를 직접 사용하면 브라우저가 자동으로 변환
- JavaScript 변환 함수는 필요 시에만 사용 (대부분 CSS로 처리 가능)
- 미디어 쿼리로 화면과 프린트를 분리하여 각각 최적화
