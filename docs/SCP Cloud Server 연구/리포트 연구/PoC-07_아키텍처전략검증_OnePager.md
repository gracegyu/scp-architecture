**Project Name**: PoC-07: 아키텍처 전략 검증 (NPM Package vs SaaS)

**Date**: 2026년 1월 6일

**Submitter Info**: SCP Cloud 개발팀

**Project Description**: SCP Cloud Report 시스템을 여러 웹 서비스에서 활용할 수 있는 최적 배포 방식을 결정합니다. NPM Package 형태의 라이브러리 방식과 중앙화된 SaaS 서비스 방식, 그리고 하이브리드 방식을 비교 분석하여 기술적 타당성, 비즈니스 모델, 유지보수성을 종합적으로 평가합니다.

**Business and Marketing Justification**:

- **시장 확장성**: 다양한 웹 서비스에 쉽게 통합 가능한 구조로 시장 점유율 확대
- **매출 모델 다양화**: Package 라이센스 vs SaaS 구독 vs 하이브리드 모델
- **기술 종속성 관리**: 고객사의 기술 스택 독립성 vs 통합 관리의 효율성
- **개발 효율성**: 중복 개발 최소화 및 일관된 사용자 경험 제공
- **확장성**: 글로벌 서비스 확장 시 배포 및 운영 효율성
- **커스터마이징 요구**: 의료기관별 특수 요구사항 대응 방안

**Risk Assessment**:

- **높은 리스크**:
  - 잘못된 아키텍처 선택 시 전체 비즈니스 모델 변경 필요
  - SaaS 방식 선택 시 초기 인프라 투자 및 운영 부담 증가
- **중간 리스크**:
  - NPM 방식 선택 시 버전 관리 및 지원 복잡성
  - 하이브리드 방식의 복잡한 아키텍처로 인한 개발 지연
  - 보안 및 규정 준수 요구사항 대응 차이
- **저위험**:
  - 각 방식 모두 검증된 배포 모델 존재
- **완화 방안**:
  - 단계적 접근 (MVP → Full Service)
  - 고객 세그먼트별 다른 배포 방식 제공
  - 마이그레이션 경로 사전 설계

**Technical Description**:

**비교 분석 대상**:

**1. NPM Package 방식**:

```typescript
// 사용 예시
import { SCP CloudReport } from '@ewoosoft/cloud-report';

const reportEditor = new SCPCloudReport({
  container: '#report-editor',
  apiEndpoint: 'https://api.customer.com',
  theme: 'custom-theme'
});
```

**장점**:

- 고객사 기술 스택 독립성
- 커스터마이징 자유도 높음
- 오프라인 사용 가능
- 라이센스 모델 유연성

**단점**:

- 버전 관리 복잡성 (각 고객사별 버전 상이)
- 일관된 UX 유지 어려움
- 보안 업데이트 배포 지연
- 중복 개발 및 지원 비용 증가

**2. SaaS 서비스 방식**:

```typescript
// iframe 임베딩 방식
;<iframe src='https://report.scp-cloud.com/editor?token=xxx'></iframe>

// API 연동 방식
POST / api / report / create
GET / api / report / edit / { id }
```

**장점**:

- 중앙화된 관리 및 업데이트
- 일관된 사용자 경험
- 즉시 보안 패치 적용
- 사용량 기반 수익 모델

**단점**:

- 네트워크 의존성
- 고객사 데이터 보안 우려
- 커스터마이징 제약
- 서비스 다운타임 영향 범위 큼

**3. 하이브리드 방식** (권장):

```typescript
// Core Engine: NPM Package
import { SCPReportCore } from '@ewoosoft/report-core'

// Cloud Services: Template, Asset 관리
const cloudServices = {
  templates: 'https://templates.scp-cloud.com',
  assets: 'https://assets.scp-cloud.com',
  sync: 'https://sync.scp-cloud.com',
}
```

**아키텍처 설계**:

**Core Components (NPM)**:

- Report Rendering Engine
- Element Management System
- Migration Tools
- Basic Templates

**Cloud Services (SaaS)**:

- Template Marketplace
- Asset Management (Logo, 이미지)
- Collaboration Features
- Analytics & Reporting

**비교 평가 기준**:

**1. 기술적 측면**:

- **확장성**: 동시 사용자 수 지원
- **성능**: 로딩 시간, 편집 반응성
- **보안**: 데이터 보호, 접근 제어
- **오프라인 지원**: 네트워크 단절 시 기능 유지

**2. 비즈니스 측면**:

- **초기 투자 비용**: 개발 및 인프라 비용
- **운영 비용**: 지속적 유지보수 및 지원 비용
- **수익 모델**: 라이센스 vs 구독 vs 사용량 기반
- **시장 진입 속도**: Time to Market

**3. 고객 만족도**:

- **통합 용이성**: 기존 시스템 연동 복잡도
- **학습 곡선**: 개발팀 적응 기간
- **커스터마이징**: 고객사별 요구사항 대응도
- **지원 품질**: 기술 지원 및 문제 해결

각 방식별로 동일한 시나리오 구현:
