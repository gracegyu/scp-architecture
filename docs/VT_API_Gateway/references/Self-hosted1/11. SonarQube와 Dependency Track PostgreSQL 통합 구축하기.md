# 11. SonarQube와 Dependency Track PostgreSQL 통합 구축하기

# SonarQube와 Dependency Track PostgreSQL 새 구축하기

## 개요

이 문서는 SonarQube와 Dependency Track을 기존 PostgreSQL을 활용하여 처음부터 새롭게 구축하는 방법을 안내합니다. 기존 운영 중인 서비스는 건드리지 않고, SonarQube와 Dependency Track만 새로 구축합니다.

## 전제 조건

- 기존 `docker-compose.onpremise.yml`로 PostgreSQL이 **운영 중**임 (건드리지 않음)
- Docker 및 Docker Compose 설치 완료
- `webnet` Docker 네트워크 생성 완료
- 기존 운영 서비스는 그대로 유지
- **기존 SonarQube/Dependency Track 컨테이너는 이미 삭제됨**

## 1. PostgreSQL에 데이터베이스 생성

기존 PostgreSQL 컨테이너에 SonarQube와 Dependency Track용 데이터베이스를 생성합니다.

```bash
# PostgreSQL 컨테이너에 접속
sudo docker exec -it abc-wbs-postgres psql -U postgres

# SonarQube용 데이터베이스 생성
postgres=# CREATE DATABASE sonarqube;

# Dependency Track용 데이터베이스 생성
postgres=# CREATE DATABASE dependencytrack;

# 생성 확인
postgres=# \l

# 종료
postgres=# \q
```

## 2. Docker Compose 파일 생성

기존 운영 중인 PostgreSQL을 활용하되, SonarQube와 Dependency Track만 구축합니다.

```bash
# Docker 폴더에서 compose 파일 생성
cd ~/Docker
nano docker-compose.sonarqube-dtrack.yml
```

**docker-compose.sonarqube-dtrack.yml** 내용:

```yaml
version: '3.8'

services:
  sonarqube:
    image: sonarqube:community
    container_name: sonarqube
    ports:
      - '9000:9000'
    environment:
      - SONAR_JDBC_URL=jdbc:postgresql://abc-wbs-postgres:5432/sonarqube
      - SONAR_JDBC_USERNAME=postgres
      - SONAR_JDBC_PASSWORD=postgres
    volumes:
      - sonarqube_conf:/opt/sonarqube/conf
      - sonarqube_logs:/opt/sonarqube/logs
      - sonarqube_extensions:/opt/sonarqube/extensions
    networks:
      - webnet
    restart: unless-stopped

  dependency-track-apiserver:
    image: dependencytrack/apiserver
    container_name: dependency-track-apiserver
    ports:
      - '8081:8080'
    environment:
      - ALPINE_DATABASE_MODE=external
      - ALPINE_DATABASE_URL=jdbc:postgresql://abc-wbs-postgres:5432/dependencytrack
      - ALPINE_DATABASE_DRIVER=org.postgresql.Driver
      - ALPINE_DATABASE_USERNAME=postgres
      - ALPINE_DATABASE_PASSWORD=postgres
      - ALPINE_DATABASE_POOL_ENABLED=true
      - ALPINE_DATABASE_POOL_MAX_SIZE=20
      - ALPINE_DATABASE_POOL_MIN_IDLE=10
    volumes:
      - dependency-track_data:/data
    networks:
      - webnet
    restart: unless-stopped

  dependency-track:
    image: dependencytrack/frontend
    container_name: dependency-track
    ports:
      - '8080:8080'
    environment:
      - API_BASE_URL=http://dtrack.ewoosoft.com:8081
    networks:
      - webnet
    restart: unless-stopped
    depends_on:
      - dependency-track-apiserver

networks:
  webnet:
    external: true

volumes:
  sonarqube_conf:
  sonarqube_logs:
  sonarqube_extensions:
  dependency-track_data:
```

## 3. 서비스 실행

**⚠️ 주의: 기존 onpremise 서비스는 건드리지 않습니다!**

```bash
# SonarQube와 Dependency Track만 실행
cd ~/Docker
sudo docker-compose -f docker-compose.sonarqube-dtrack.yml up -d

# 컨테이너 상태 확인
sudo docker ps

# 로그 확인 (초기 설정에 시간이 걸릴 수 있음)
sudo docker logs -f sonarqube
sudo docker logs -f dependency-track-apiserver
sudo docker logs -f dependency-track
```


## 7. 문제 해결

### **컨테이너 재시작**

```bash
# 특정 서비스만 재시작
sudo docker-compose -f docker-compose.sonarqube-dtrack.yml restart sonarqube
sudo docker-compose -f docker-compose.sonarqube-dtrack.yml restart dependency-track-apiserver
sudo docker-compose -f docker-compose.sonarqube-dtrack.yml restart dependency-track

# 모든 서비스 재시작
sudo docker-compose -f docker-compose.sonarqube-dtrack.yml restart
```

### **로그 확인**

```bash
# 실시간 로그 확인
sudo docker logs -f sonarqube
sudo docker logs -f dependency-track-apiserver
sudo docker logs -f dependency-track
sudo docker logs -f abc-wbs-postgres
```

### **서비스 완전 재시작**

```bash
# 모든 서비스 중지 후 재시작
cd ~/Docker
sudo docker-compose -f docker-compose.sonarqube-dtrack.yml down
sudo docker-compose -f docker-compose.sonarqube-dtrack.yml up -d

# 상태 확인
sudo docker ps
```

### **Frontend API 연결 문제 해결**

#### **405 에러 (Method Not Allowed) 해결**

Frontend가 자기 자신으로 API 요청을 보내는 경우:

```bash
# 1. 컨테이너 상태 확인
sudo docker ps | grep dependency

# 2. Frontend 환경변수 확인 (API_BASE_URL이 올바른지)
sudo docker exec dependency-track env | grep -i api

# 3. Frontend 로그 확인
sudo docker logs dependency-track

# 4. API 서버 로그 확인
sudo docker logs dependency-track-apiserver

# 5. 네트워크 연결 테스트
sudo docker exec dependency-track nslookup dependency-track-apiserver
sudo docker exec dependency-track curl -I http://dtrack.ewoosoft.com:8081/api/version
```

#### **API 연결 설정 수정**

Frontend가 API 서버를 올바르게 찾지 못하는 경우, 환경변수를 명시적으로 설정:

```bash
# 컨테이너 재생성 (환경변수 추가)
sudo docker-compose -f docker-compose.sonarqube-dtrack.yml down
sudo docker-compose -f docker-compose.sonarqube-dtrack.yml up -d
```

### **80 포트 Nginx 연결 호환성**

**Nginx 설정 호환성**:

- `sonarqube` 컨테이너 → Nginx에서 `http://sonarqube:9000`로 연결 (변경 없음)
- `dependency-track` 컨테이너 → Nginx에서 `http://dependency-track:8080`로 연결 (원래대로)
