# 99. Buildmachine2 복구 절차

## 복원 절차

### **0단계: 사전 준비**

**새 서버에 Docker 설치**

```bash
# Docker 설치 확인
docker --version
docker-compose --version
```

**중요: 복원 순서 (3단계)**

1. **1단계**: Jenkins 복원 (Job, Credential, 플러그인 포함)
2. **2단계**: 데이터/정적자원 복원 (PostgreSQL, Nginx 설정, Web/Uploads)
3. **3단계**: Jenkins 파이프라인으로 WBS/SQ/DT 컨테이너 배포

### **1단계: Docker 컨테이너 생성**

### **1단계: Jenkins 컨테이너 생성 (먼저)**

**Jenkins 컨테이너만 생성하면 됩니다**

```bash
# Jenkins 컨테이너 생성 (아직 시작하지 않음)
docker run -d \
  --name jenkins-server \
  -p 8090:8080 \
  -p 50000:50000 \
  -v jenkins_home:/var/jenkins_home \
  jenkins/jenkins:lts
```

✅ 중요: 사전 설치는 Postgres만. `abc-wbs-backend`, `abc-wbs-ywebsocket`, `sonarqube`, `dependency-track`은 3단계에 설치합니다.

### **2단계: Jenkins 복원**

### **2단계: Jenkins만 복원 (먼저)**

**Jenkins만 먼저 복원합니다**

```bash
# 복원 스크립트 다운로드
git clone https://your-azure-devops-repo-url bm2databackup
cd bm2databackup

# 실행 권한 부여
chmod +x restore_jenkins_only.sh

# AWS 자격증명 설정
export AWS_ACCESS_KEY_ID="your-access-key"
export AWS_SECRET_ACCESS_KEY="your-secret-key"
export AWS_DEFAULT_REGION="ap-northeast-2"

# Jenkins만 복원
./restore_jenkins_only.sh 20241221_020000
```

### **2단계 이후: 데이터/정적자원 복원 (DB, Nginx, Web, Uploads)**

Jenkins가 복원되면 데이터와 정적자원을 복원합니다.

```bash
# DB/정적자원 복원 (PostgreSQL, Nginx 설정, Web, Uploads)
./scripts/restore/restore2_es_buildmachine2.sh 20241221_020000
```

Nginx 컨테이너가 아직 없어도 스크립트는 설정 디렉터리만 복원하고 넘어갑니다. 이후 컨테이너를 만들 때 해당 디렉터리를 마운트하면 설정이 적용됩니다.

### **3단계: WBS/SonarQube/Dependency-Track 수동 설치 (기존 매뉴얼 기반)**

운영 표준에 맞춰 각 서비스를 수동으로 설치합니다. 아래 문서를 참고하세요.

- Docker 설치 선행: `docs/2.Docker설치.md`
- 네트워크/연동 가이드: `docs/3. SonarQube, Dependency Track 구축을 위한 Network 설정.md`

예시 절차(참고용, 실제 값은 환경에 맞게 변경):

```bash
# 3-1) WBS Backend / Y-WebSocket
# docker-compose 예시 (경로: "\b abc_wbs/docker-compose.onpremise.yml")
docker-compose -f "\b abc_wbs/docker-compose.onpremise.yml" up -d backend y-websocket

# 3-2) SonarQube
docker run -d --name sonarqube -p 9000:9000 sonarqube:community

# 3-3) Dependency-Track (API/Frontend)
docker run -d --name dependency-track-apiserver -p 8081:8080 dependencytrack/apiserver
docker run -d --name dependency-track -p 8080:8080 dependencytrack/frontend

# 필요 시 환경변수/볼륨/네트워크는 내부 표준에 맞춰 추가
```

주의: 3단계는 수동 설치 단계입니다. Jenkins Job을 동시에 사용하지 마세요(중복 배포 방지).

## 📝 참고사항

### **복원 순서**

1. **Jenkins 먼저**: Jenkins Job이 다른 컨테이너를 배포하므로 먼저 복원
2. **자동 배포**: Jenkins Job 실행하면 GitHub에서 소스 가져와 컨테이너 빌드
3. **수동 복원 불필요**: `abc-wbs-backend`, `abc-wbs-ywebsocket`는 Jenkins가 자동 배포

### **파일 설명**

- `restore_jenkins_only.sh`: Jenkins만 복원 (1단계)
- `restore_es_buildmachine2.sh`: 전체 복원 (PostgreSQL 포함, 선택 사항)
- **참고**: docker-compose 파일 불필요 - Jenkins가 자동으로 모든 컨테이너 생성

### **Jenkins 구조**

- **Repository**: GitHub (`https://github.com/gracegyu/abc-wbs.git`)
- **Branch**: `/Ewoosoft`
- **Jenkinsfile**: `jenkins/backend.Jenkinsfile`
- **Credential**: GitHub 접근용 credential 복원됨

## 🧩 외부 의존 서비스 재구축(수동)

다음 서비스들은 백업/복원 스크립트의 대상이 아니므로, 신규 서버에서는 별도로 재구축해야 합니다.

### **1) Nginx (역방향 프록시)**

복원 스크립트가 Nginx 설정을 적용하려면 컨테이너 이름이 `nginx-proxy`여야 합니다. 먼저 컨테이너를 생성한 뒤, Jenkins 복원 후 스크립트를 실행하세요.

```bash
docker run -d \
  --name nginx-proxy \
  -p 80:80 \
  -v nginx_data:/etc/nginx \
  nginx
```

참고: Nginx 설정 파일은 백업에 포함되어 있으므로, 컨테이너만 만들어 두면 복원 스크립트가 자동으로 설정을 반영합니다.

### **2) Dependency-Track**

운영 환경에서 사용하던 포트(프론트엔드 8080, API 8081)를 기준으로 간단 생성 예시입니다.

```bash
# API 서버
docker run -d \
  --name dependency-track-apiserver \
  -p 8081:8080 \
  dependencytrack/apiserver

# 프론트엔드
docker run -d \
  --name dependency-track \
  -p 8080:8080 \
  dependencytrack/frontend
```

필요 시 영속 볼륨/DB 연동은 제품 문서에 따라 추가하세요.

### **3) SonarQube**

```bash
docker run -d \
  --name sonarqube \
  -p 9000:9000 \
  sonarqube:community
```

운영 데이터가 있다면 별도 백업/복원 절차를 수행하세요.

### **4) Azure DevOps Agent (Self-hosted)**

조직/토큰/에이전트 풀 정보를 환경 변수로 지정하여 실행합니다. 이미지 이름은 환경에 맞게 조정하세요.

```bash
docker run -d \
  --name azp-agent-linux1 \
  -e AZP_URL="https://dev.azure.com/<ORG>" \
  -e AZP_TOKEN="<PERSONAL_ACCESS_TOKEN>" \
  -e AZP_POOL="Default" \
  -e AZP_AGENT_NAME="$(hostname)-1" \
  mcr.microsoft.com/azure-pipelines/vsts-agent:ubuntu-22.04
```

보안 참고: 토큰은 최소 권한으로 발급하고, 사용 후 교체를 권장합니다.

## ✅ 외부 서비스 점검 체크리스트

- Nginx 컨테이너(`nginx-proxy`) 생성 및 실행
- Dependency-Track 프론트엔드/API 실행 확인 (8080/8081)
- SonarQube 실행 확인 (9000)
- Azure DevOps Agent 온라인 상태 확인 (Agent Pool)
