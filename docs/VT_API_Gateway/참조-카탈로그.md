> **GW 레포 명명**: 본체 `vt-api-gateway`와 동일하게 Azure `es-platforms` 프로젝트·`vt-api-gateway-*` sibling 패턴. Console 생성 전 이름 합의. **단 Infra는 별도 레포가 아니라 조직 표준 `es-infra`에 편입될 가능성**(아래).

> **`es-infra` 상세 (GW ③-I·§3.1·§4.5.1·§7.3.5 직결).** Azure DevOps **`platforms`** 프로젝트(앱 코드 `es-platforms`와 분리). **IaC = Terraform**(≥1.10 · AWS provider ~6.0 · 기본 리전 **`ap-northeast-2` 서울** = GW v1.0 단일 리전과 일치) — 상태 백엔드 S3(`ewoosoft-terraform`) 네이티브 락. 환경=**디렉터리 기반**(`terraform/envs/<dev|mgmt|stg|prod>`), 계층=**7단(순서·하향 참조)**: `network→security→data→platform→compute→edge→apps`.
> - **GW가 얹히는 지점**: **EKS**(GW pods, Karpenter 프로비저닝)·**ElastiCache/RDS/S3/ECR**(§3.1.2 DB·캐시·이미지)는 `data/`, **로드밸런서·EKS·리전 ACM**은 `platform/`, **앱 워크로드 아이덴티티(pod SG·Secret·EKS Pod Identity=IRSA류)**는 `apps/`(`modules/app`).
> - **DNS**: `aws_route53_zone`은 **`network/`에서 shell 생성**, 레코드는 트래픽 소유 계층이 작성 → GW **apex `gw.vatech.com`·webhook 호스트**(§4.5.1)·**GeoDNS**(§7.3.5)가 여기 매핑. **앱 온보딩 = `<app>_lb` A-alias 레코드 추가 + Istio 라우트**(공유 ALB, 신규 ALB 생성 아님).
> - **인그레스/라우팅**: **Istio Ambient Mesh + Gateway API**가 host/path 라우팅(ADR-11 target-routed proxy와 연계 검토). **egress = NAT**(non-prod 단일 / prod AZ당 1개) → GW **고정 egress EIP 집합·AXS whitelist**(§2.1.1·§7.5.3)의 인프라 근거.
> - **짝 레포 `es-gitops`**(ArgoCD GitOps): 플랫폼/앱은 GitOps로 배포(App-of-Apps). *Terraform=인프라 / GitOps=앱* 분리.
> - **함의(R5)**: 조직 인프라 표준이 **Terraform**임이 확인됨 → SRS §6.6.2·Agenda R5(“IaC = CDK vs Terraform”) 판단의 강한 입력(조직 표준=Terraform).
> - 로컬 참고 문서: `es-infra/README.md`·`CLAUDE.md`(규칙 SSOT)·`docs/eks-platform-plan.md`(EKS 플랫폼 As-Built, 2026-06-25)·`docs/vt-prod-org-consolidation-cost-simulation.md`·`docs/*migration*`.
